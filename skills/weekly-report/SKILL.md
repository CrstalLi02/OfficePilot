# 周报撰写

## 何时使用
用户提供了本周做过的事（可能是零散的聊天记录、待办清单、会议纪要或工作区里的文件），需要整理成一份可直接发出的周报。

## 流程
1. **收集素材**：用户只说"写周报"而没给内容时，先用 workspace_search 搜索本周的会议纪要、待办、项目文档；仍然不够再向用户要要点，不要编造工作内容。
2. **归类**：把条目归到"重点成果 / 进行中 / 问题与风险 / 下周计划"四类；同一件事的多条记录合并。
3. **量化**：每条成果尽量写出可验证的结果（数量、百分比、时间节点、上线 / 交付状态）。素材里没有数字就如实描述，不要估算。
4. **按受众取舍**：
   - 给直属领导：成果和风险在前，每条 1–2 句；
   - 给团队：可以保留执行细节和协作对象；
   - 给跨部门：去掉内部术语，补一句背景。
5. **成稿**：按 `{baseDir}/assets/template.md` 的结构，用 md_generate 生成（用户要 Word 时用 doc_generate）。

## 写作标准
- 标题：`【周报】姓名 · 部门 · 第 N 周（日期范围）`
- 每条以动词开头："完成…""推进…""修复…"，避免"做了一些…"。
- 风险必须写清楚影响和需要的支持，例如"接口联调延期 2 天，需要后端排期支持"。
- 下周计划要具体到可检查的结果，不写"继续推进"。
- 全文控制在一屏到两屏之间；用户要求简短版时只保留成果和计划。
