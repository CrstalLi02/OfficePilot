# 简历优化

## 原则
- **真实第一**：只改写表达，不虚构经历、职责、公司或数字。用户提供的事实不够时，标出"建议补充：…"，由用户确认后再写入。
- **对照岗位**：先从岗位描述（JD）里提取 5–8 个关键能力和关键词，再看简历里哪些经历能对应。

## 流程
1. **拿到材料**：简历原文（用户粘贴，或用 workspace_read 读取文件）和目标岗位 JD。没有 JD 时，请用户说明目标岗位方向。
2. **差距分析**：列出"JD 要求 → 简历中的对应证据 → 缺口"，缺口要如实告诉用户。
3. **重写每条经历**，格式为：动词开头 + 做了什么 + 用什么方法 / 技术 + 可验证的结果。
   - 改写前："负责后台开发"
   - 改写后："用 Go 重构订单服务的并发调度，P95 延迟从 320ms 降到 140ms"（数字必须来自用户提供的事实）
4. **结构与篇幅**：应届或 5 年以内一页；与岗位相关的经历放前面；技能栏只写能在面试中讲清楚的。
5. **一致性检查**：时间线不重叠、技术栈前后一致、同一项目的数字在各处一致。
6. 输出：改写后的简历（md_generate 或 doc_generate），以及一份"修改说明 + 需要用户确认的事实"清单。

## 面试准备提示
对每条量化结果，提醒用户准备好：数字怎么测出来的、基线是什么、自己具体负责哪一部分。
