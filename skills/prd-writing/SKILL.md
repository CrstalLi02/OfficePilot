# PRD 撰写

## 流程
1. **澄清最少的必要信息**：目标用户、要解决的问题、成功指标。用户没给时做合理假设，并在文档"假设与待确认"一节列出，不要反复追问。
2. **用户场景先于功能**：先写 2–4 个具体场景（谁、在什么情况下、想完成什么、现在的痛点），再推导功能。
3. **功能需求表**：每条需求有编号、优先级（P0 / P1 / P2）、描述、验收标准；验收标准要可测试（输入 → 预期结果）。
4. **补齐容易遗漏的部分**：异常与边界情况、权限、数据埋点、兼容性、性能指标、对其他系统的影响。
5. 按 `{baseDir}/assets/prd-template.md` 的结构，用 doc_generate 生成 Word（format 用 prd）；需要流程图时同时调用 drawio_generate。

## 质量标准
- 指标必须可衡量，例如"新用户 7 日留存从 20% 提升到 25%"，而不是"提升用户体验"。
- P0 需求控制在一次迭代可以完成的范围内。
- 每条需求都能追溯到某个场景，没有场景支撑的需求放进"后续规划"。
