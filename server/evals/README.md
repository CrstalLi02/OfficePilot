# Agent 路由评测

检查 Agent 在**第一轮**是否选对了工具。它复用线上的 `resolve_routing` 和 `build_initial_request` 组装请求，每条用例调用一次 LLM，只判断 tool_calls，不实际执行工具。

## 运行

```bash
cd server
cargo build --release
./target/release/walioffice eval --label baseline --repeat 3
```

模型地址和 key 读取 `.env` 中的 `LLM_TEXT_*` 配置，用 `--model` 可以覆盖模型名。报告写到 `evals/reports/<时间>-<模型>-<label>.md`，同目录下还有一份 `.json` 明细。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--cases` | `evals/routing.jsonl` | 用例文件 |
| `--repeat` | 1 | 每条用例重复次数（线上 temperature=0.7，建议 ≥3） |
| `--concurrency` | 4 | 并发请求数 |
| `--filter` | – | 只跑 id 或分类包含该文本的用例 |
| `--label` | – | 报告标签，例如 `baseline`、`m2` |

mock LLM（`dev/mock_llm.py`）总是调用第一个可用工具，只能用来验证评测流程本身，**分数没有意义**。

## 用例格式（`routing.jsonl`，一行一条）

```json
{"id":"ppt-basic","category":"ppt","message":"帮我做个PPT",
 "tool_kind":null, "attachments":[{"kind":"image|text","name":"a.png","text":"..."}],
 "history":[{"role":"user","content":"..."}],
 "expect":["必须全部调用"], "expect_any":["至少调用一个"], "forbid":["不允许调用"], "expect_no_tool":false}
```

- 如果调用了 `propose_plan`，计划 `steps[].tool` 里列出的工具也算作"已选择"。M2 引入计划确认后，用例无需修改。
- 图片附件统一使用 1x1 占位 PNG，测的是意图路由，不测识图能力。
- 多产物用例只检查第一轮有没有走对方向，不检查最终是否交付了全部文件。

## 评测结果（2026-10-16，deepseek-v4-pro，每条 3 次）

对比对象：规则版意图识别（commit 4d970cf，45 条用例）与当前版本（删除规则、改用工具描述 + Craft/Plan/Ask 模式，并新增技能、工作区、数据分析工具，63 条用例）。报告原文见 `reports/`。

| 版本 | 共同 45 条 · 严格 | 共同 45 条 · 含准备步骤 | 全部 63 条 · 含准备步骤 | 误调用禁止工具 |
|---|---|---|---|---|
| 规则版基线 | 96.3% | 97.8% | — | 0 次 |
| 当前版本（第 1 次） | 91.1% | 99.3% | 99.5% | 0 次 |
| 当前版本（调整技能描述后） | 89.6% | 96.3% | 97.4% | 0 次 |

如何解读：

- **严格**：第一轮就调用了用例期望的工具。当前版本多了技能、工作区、数据工具后，模型常先做一步合理的准备再生成，例如做汇报 PPT 前先 `use_skill` 加载汇报结构技能；用户只给了文件名时先 `workspace_search` 找到文件，再 `data_query`。这些情况严格判定为失败。
- **含准备步骤**：第一轮只调用了准备类工具（加载技能、找 / 读文件、数据画像、搜索、提交计划），且没有调用任何禁止的工具，也计为通过。
- 同一版本两次运行相差约 3 个百分点（temperature 0.7、每条 3 次），版本之间的差异在这个波动范围内。结论：**删除 929 行规则式意图识别后，工具选择准确率没有可测量的下降，三轮运行都没有出现误调用禁止工具**。
- 根据结果做的调整：汇报结构技能的描述限定为“需要说服听众的汇报场景”，`ppt-en`（产品介绍 PPT）不再多走一步加载技能，通过率 33% → 100%。
- 已知局限：只评测第一轮；带图片的用例使用 1×1 占位图，模型偶尔会请用户重新上传；第二次运行中有 1 次网络错误被计为失败（之后评测会对网络错误自动重试一次）。

### 定时任务用例（C1）

新增 4 条 `schedule` 类用例（每周周报、每日简报、每月清单、查看已有定时任务）。deepseek-v4-pro ×5：19/20 通过，唯一一次未通过是先 `use_skill` 加载周报技能（计入“含准备步骤”）。工具描述已说明周期性请求应直接创建，技能写进 `skills` 参数、到点再加载。
